# Where the code deliberately diverges from the plan

Moved out of the root `CLAUDE.md`, which points here.

The plan contains full code listings. Tasks 10–14 were implemented from them, but the following places are **intentionally different** and should not be "corrected" back to the plan's text. Each was verified against the real catalog before changing.

| Where | Plan said | Why the code differs |
| --- | --- | --- |
| `persona/client.py:scrub` | substring match on `leak_terms` | `"lease" in "please"` and `"ad " in "bad "` — a plain-English reply got discarded as a leak. Now anchored at a word start, with a trailing space meaning whole-word. |
| `persona/templates.py:_quoted_error` | always wrap as `It says "…"` | `ad.account_locked`'s `error_text` already opens with "It says", so it double-prefixed. Never strips text, so the raw `error_text` stays a substring of what is spoken. |
| `session/ticket.py:WORK_STOPPING` | omitted `ad.offboarded_reactivation` | It is a can't-sign-in fault; priority tracks impact on the person, not who ends up fixing it. |
| `world/invariants.py:capture_baseline` | `allowed_dns` from `network.dns_servers` | Broke capture-after-apply for `net.static_dns_misconfig`, which reported itself as the technician's collateral damage. Now snapshots machine state like every other field. |
| `session/queue.py` baseline | re-snapshot on every arrival | Laundered the technician's mistakes: damage done on ticket 1 vanished when ticket 2 arrived. `forgive()` accumulates instead. |
| `session/afteraction.py` verdict | branched on `disposition_correct` | That flag folds in `fault_cleared`, so closing-without-fixing was reported as a wrong escalation, and the last branch was unreachable. Branches on the chosen `Disposition` now. |
| `session/afteraction.py:touched_before_asking` | `questions == 0` | True whenever nobody mutated anything, so a correct read-only escalation was accused. Requires an actual mutation. |
| `grading.py:questions_before_first_mutation` | count all tech turns if the first call was a read | Counted questions asked *after* the fix as diligence. `ChatTurn` gained an `at` stamp so the two logs interleave. |
| `web/templates/layout.html` | render an org display name from `World` | `Organization` has no `name` field, only `domain: meridian.local` — "Meridian Freight Co." is hardcoded static branding text, not derived from world data. |
| `web/routes/tools.py:run_tool` | build a `ToolCall` for the unknown-tool branch and return it | The plan's version never calls `log.record(call)` on that path, so the failed call never reaches `log.calls` and never renders — `_toolout.html` would silently show nothing instead of the "not recognized" message. Now explicitly recorded, same as every call `DispatchTool.invoke` handles. |
| `web/templates/_queue.html` | Task 16 prose: show "a truncated opening line" | Task 19's `test_a_full_ticket_can_be_worked_through_http` asserts `ticket.report_text in client.get("/").text` — the two tasks' own descriptions conflict. The queue row renders the full `report_text`, not a 60-char slice of `symptoms.opening`. |
| `web/routes/events.py` | advance `world.clock` inline in the per-connection `stream()` loop | A first pass did this directly, but every open SSE connection (a second browser tab, an `EventSource` reconnect) runs its own copy of that loop against the same shared clock, so N connections made time run N times too fast. `AppSession.last_tick_at` plus `advance_clock_if_due()` now guard the increment so it happens at most once per real second regardless of connection count — caught by automated PR review, not the original test suite (see `tests/test_web_events.py`). |
| `web/templates/_ticket.html` / `_queue.html`: `report_text` | mark `report_text \| safe` to preserve embedded quotes | Rendering unescaped output was an XSS opening: `AppSession.build()` accepts any `Persona`, and a future model-backed one (`LMStudioPersona` already exists) could return markup that `\| safe` would let the browser execute. `report_text` is now autoescaped like everything else; tests compare against `markupsafe.escape(text)` instead of the raw string. Caught by automated PR review. |
| `tests/test_end_to_end.py` | resolve each fault via `session.env.execute()` directly | The only real HTTP tool call was a fixed `ad get-user` read, so the test's own claim — "proof that a full ticket can be worked start to finish through the HTTP surface only" — didn't hold for the repair step. `resolve_via_http()` now posts the fault's canonical fix through `POST /ticket/{id}/tool` via a `HTTP_FIX` command table, with a second test asserting every non-escalation fault has a table entry. Caught by automated PR review. |
| `tests/test_persona_binding.py`: leak-terms-in-prompt check | assert each leak term is absent from the prompt as a raw substring | The prompt legitimately carries the fault's own `error_text`, and `ad.account_locked`'s ends "contact my system administrator" — the `"ad "` term matched inside "administrator", failing a prompt that leaks nothing. Now asserts `scrub(prompt, leak_terms) is not None`: the same word-start-anchored rule layer 3 applies, and the one the conformance harness already proves symptom text satisfies. |
| `persona/client.py`: `LMStudioPersona.degraded` | `for_fault` returns "a new instance sharing the client, model and fallback"; `degraded` stays a plain instance attribute | After Task 1 every model call goes through a *binding*, never the persona `SessionQueue` holds — so a per-instance flag records an outage on an object nothing reads, and Task 2's banner (`AppSession.degraded` → `queue.persona.degraded`) would stay dark through one. The flag is now a `_Degradation` holder passed to each binding by reference, so degradation travels back to the origin while leak terms stay per-ticket. |
| `persona/client.py:make_client` | `OpenAI(base_url=..., api_key=...)` with no transport settings | The module docstring promises a model that is "down, slow, or absent" degrades gracefully, but the openai SDK's default timeout is 600s — a wedged LM Studio would hang the page for ten minutes rather than fall back. `make_client` now sets `REQUEST_TIMEOUT_SECONDS` (30s) and `TRANSPORT_RETRIES` (0): the persona layer's fallback *is* the retry strategy, so retrying underneath it only delays the inevitable. |
| `web/templates/layout.html`: degraded banner | "render a banner in `layout.html` when it is true" | Rendered at page load only, the banner would almost never appear: degradation starts mid-session, and in an HTMX app the next full page load may never come. The element is always rendered (`hidden` when healthy) and the existing SSE handler in `base.html` toggles it, so `events.py`'s payload carries `degraded` too. |
| `web/routes/events.py`: `build_payload` | payload dict built inline in the `stream()` loop | Asserting on the new `degraded` field meant driving `/events` through `TestClient`, and the stream loop never terminates — the test hung rather than failed. The payload builder is now a module-level function, matching how `advance_clock_if_due` was already split out of the same loop for the same reason, and `tests/test_web_events.py`'s existing habit of testing that route's pieces directly. |
| `env/simulated.py:_read_share_access` | plan silent on this; not in Task 4's stated file list | Task 4's `drive.stale_mapping` distractor is the first thing ever to put a value in `machine.mapped_drives` that isn't a key in `world.shares` (the point of a *stale* mapping). The old code indexed `world.shares[...]` directly, which would raise `KeyError` — an unhandled 500 — the moment a player ran `Get-PSDrive -Name Z:` against a seeded machine, since `PowerShellConsole.target_key` passes whatever drive letter the player types straight through. Now a missing share renders the same "network path was not found" text the DNS-failure branch already uses, which is also what real Windows shows for a mapping whose target no longer resolves. |
| `tests/test_catalog.py:test_v1_catalog_is_complete` | plan silent on this; not in Task 7's stated file list | The name predates Phase 2a and enumerates a fixed 10-fault set. `print.server_spooler_stopped` registers like any other fault and is picked up by the parametrized conformance tests automatically, but this one test hardcodes the whole id set and would otherwise fail the moment an 11th fault exists — it now includes the new id, with a comment noting the name is historical rather than a hard boundary. Task 15's two mail faults hit the same hardcoded set and are now included too. |
| `tests/test_catalog.py:test_exactly_two_faults_are_escalate_correct` | plan silent on this; Task 15 adds a third escalate-correct fault | `mail.external_forwarding_rule` (Task 15) is escalate-correct for a reason distinct from the existing two, so the count and the assertion both grow to three. Renamed `test_exactly_three_faults_are_escalate_correct` rather than leaving a stale "two" in a now-three-item assertion. |
| `tests/test_end_to_end.py:HTTP_FIX`/`TARGET_FIELD` | Task 16's stated file list, not Task 15's | Every prior escalate-incorrect fault has kept this table current in the same task that registers the fault (`print.server_spooler_stopped` already has an entry despite Task 16's own text listing it as something still to add) — the guard test fails immediately otherwise, since it iterates `all_faults()`. `mail.mailbox_full` → `("mail", "set-quota")` / `"sam"` added here, consistent with that precedent; Task 16 still owns the new cascade/tier-2/mail/distractor end-to-end tests themselves. |
| `tests/test_grading.py:test_every_fault_produces_a_report_with_a_bound_shortest_path` | plan silent on this; not in Task 7's stated file list | Predates cascades: it derived the ticket's `sam` from `placement.kind == "user"` else `assigned_to`, which is `None` for a print server placement and raised `KeyError: None` indexing `world.org.users`. Now uses `session/queue.py:resolved_reporters(world, fault, placement)[0]`, the same resolution the scheduler itself uses, which covers both the single-reporter case and a cascade fault's own `reporters()`. |
| `session/tier2.py:review_escalation` | "Tier-2 judges two things, in this order: 1. Is the note usable? ... 2. Does this belong to tier-2 at all?" | The plan's own worked examples contradict that stated order: `test_a_fixable_fault_is_bounced_back` escalates `ad.account_locked` with a note that names no evidence at all ("please fix") and still expects the *scope-boundary* bounce text, not the *evidence-missing* one. Checking ownership (`escalation_is_correct`) first reconciles every example: a fixable fault is bounced regardless of note quality, and the evidence check only ever gates the accept path for a fault that genuinely belongs to tier-2. |
| `tests/test_web_escalate.py`: leak-terms-in-bounce-text check | assert each leak term is absent from the whole response body as a raw substring | The bounce response embeds the full `_ticket.html` (chat, priority form, tools `div` with `hx-trigger="load"`, both action buttons), and a stripped term like `"ad"` is a substring of ordinary template chrome ("already", "load") that has nothing to do with leaking the cause — the exact false-positive class `persona/client.py:scrub()` exists to avoid. The test now asserts `scrub(bounce_text, fault.leak_terms) is not None` against the tier-2 response text itself (`ticket.chat[-1].text`), the same check `test_persona_binding.py` already uses for the analogous prompt-leak problem. |
| `tests/test_kb.py` | `import vitsc.faults.catalog  # noqa: F401` at module scope, to trigger fault registration | `all_faults()` (`faults/registry.py`) already imports `vitsc.faults.catalog` internally on every call — every other test module in the suite relies on that self-registration rather than a standalone import. The plan's explicit import was therefore genuinely unused and pylint flagged it (`unused-import`); dropped rather than suppressed, matching this file's own preference for fixing a finding over adding to the disable list. |
| `session/afteraction.py:AfterAction.kb_suggestions` | `list[str]` | Rendered `| safe` in `_afteraction.html`, unlike `report_text`'s autoescaping (see the `report_text` row above). Not a contradiction: `report_text` can originate from a persona — user-adjacent, untrusted text — while every `kb_suggestions` string is built in `afteraction.py` itself from `fault.kb_articles` (static catalog data) and `Distractor.note` (static catalog data), never from a ticket, a chat turn, or model output. Marking trusted, locally-authored HTML `| safe` is not the vulnerability that motivated the `report_text` fix. |
| `env/simulated.py:_do_mail_set_quota` | plan silent on the exact wording; not in Task 14's stated file list | Task 14's own test (`test_a_missing_parameter_is_reported_not_raised`) asserts the tool-level rejection names `quota_mb`, the args-dict key the player actually types. The env layer's error originally read `-ProhibitSendQuota must be a number.` (the real cmdlet's parameter name) and never contained that substring. Changed to `-quota_mb must be a number.` — the args key, not the PowerShell-native name — since `MailConsole` passes that key straight through with no renaming in between. |
| `faults/catalog/mail.py:ExternalForwardingRule.is_present` | the plan, and PR #9 as merged, gate on "any rule forwarding outside `meridian.local`" | `apply()` sets the mailbox-level `forwarding_smtp` as well as the rule (the plan says so, and `mail.mailbox` renders `ForwardingSmtpAddress`), but no action in `env/simulated.py` clears it. A rules-only gate therefore let `mail.remove_rule` drive `is_present()` false on a mailbox that was still redirecting every message out of the company. The gate now covers both halves, so removing the visible rule leaves the fault present — which is the lesson the fault exists to teach. |
| `faults/catalog/mail.py:ExternalForwardingRule.canonical_resolutions` | plan silent; PR #9 as merged declares a `mail.remove_rule` path | Follows from the row above: with the gate covering `forwarding_smtp`, no sequence of existing actions clears the fault, so the honest declaration is `[]` — the same escalate-correct-plus-empty-resolutions encoding `endpoint.failing_disk` already uses, and the branch `tests/test_catalog.py` already carries for it. |
| `env/simulated.py:_read_mail_rules` | plan silent; a Task 13 file, not in Task 15's stated file list | The `ForwardTo` column was a fixed `:<28`, which does not pad a value wider than itself — the first realistic forwarding address ran straight into `DeleteMessage` with no separating space (`...@mailrelay-secure.exampleTrue`). Nothing had exercised it: the only rule in any prior test was `x@example.com`. Widths are now sized from the content, the way `Format-Table` does. Found by driving the tool live, not by the suite. |
| `session/ticket.py:accept_escalation` | Task 9: `accept_escalation(at)` closes the ticket | The bounce path records tier-2's words (`reopen(text)`); the accept path discarded them. `Fault.escalation_reason` is spoken in exactly one place — `tier2.py`'s acceptance string — so an accepted escalation, the *correct* disposition for three faults now, taught the player nothing about why it was not theirs. `accept_escalation(text, at)` now appends the tier-2 turn, `AfterAction.tier2_note` carries it, and `_afteraction.html` renders it autoescaped (it is static catalog text, but unlike `kb_suggestions` it arrives via a `ChatTurn`, so it is escaped like any other). |
| `tests/test_end_to_end.py`: `HTTP_FIX` | Task 16 adds the `mail.mailbox_full` entry | `test_every_resolvable_fault_has_an_http_fix_mapped` fails the moment the fault registers, so deferring the one-line entry to the next task would leave the suite red in between. Added with the fault instead. |
| `tests/test_catalog.py:test_exactly_two_faults_are_escalate_correct` | plan silent; not in Task 15's stated file list | Hardcodes the escalate-correct roster, the same shape as `test_v1_catalog_is_complete`. Renamed to `..._three_...` and extended, with the docstring now naming the one-reason-each rationale so the next addition has to justify itself rather than pad the set. |
| `tests/test_end_to_end.py:test_every_resolvable_fault_has_an_http_fix_mapped` | Task 16: "the existing guard must keep proving that only escalate-correct faults are absent from the table, not merely that the table is non-empty" | Containment in one direction did not do that: it caught a *missing* entry but not an entry for a fault that no longer exists, nor an escalate-correct fault wrongly listed. Now `set(HTTP_FIX) == {resolvable ids}`, which fails in both directions, with `test_every_http_fix_names_a_real_command_and_target_field` covering the other way an entry can be wrong — present, but naming a command the tool does not register or a command with no `TARGET_FIELD`. |
| `tests/test_end_to_end.py`: a fifth Task 16 test | Task 16 lists four tests, `test_a_mail_ticket_can_be_worked_through_http` among them (body elided as `...`) | The mail slice is two faults with *opposite* correct dispositions, and one test can only exercise one of them. `test_an_escalate_correct_mail_ticket_is_accepted_through_http` covers the other, and is the only end-to-end proof that `escalation_reason` now reaches the rendered report — the Task 9 defect fixed alongside Task 15. |
| `session/queue.py:open_ticket` | Phase 1: `rng.choice(candidates)` over `(fault, placement)` pairs | That weights each fault by its placement count, which is an accident of the estate rather than a decision: the cascade (one placement) was dealt twenty times less often than a mail fault (twenty). Now picks the fault first, weighted by difficulty, then a placement uniformly. Measured before and after in the commit that made the change. |
| `tests/test_queue.py`: three tests | one arrival is one ticket | Only ever true because the cascade was nearly unreachable at 0.8% of the draw. At ~9% the fixed seed deals it, and all three broke: a no-duplicate check that compared fault+placement pairs against the *ticket* count (which asserts cascades cannot happen), a tick-interval test that counted tickets, and a reporter test that called `open_one()` `MAX_ACTIVE` times and ran off the end. Tests corrected rather than the scheduler weakened. |
| `SessionQueue.__init__` | positional parameters throughout | `shift_ends_at` took the queue past pylint's positional-argument limit. Fixed by making `distractor_count` and `shift_ends_at` keyword-only — better API design regardless of the linter, and every call site already passed them by name — rather than bumping a second design limit. |
| `faults/base.py:_printer_key` | plan silent; predates device-level printer placements | Split `at.key` on `/` and took index `[1]` unconditionally. Phase 2b's printing faults place on a bare printer name, so `_sentinels` — which computes every sentinel eagerly for every `bind()` — would have raised `IndexError` on the first resolution. Both printer helpers now accept either shape. |
| `session/queue.py:reporter_sam` | printer placements "carry a `hostname/printer` key" | Same cause, different symptom: a bare printer name resolved to no machine, so `resolved_reporters` returned `[]` and a device-level fault opened a ticket for nobody. Resolves a bare name to the first workstation holding the printer, matching `_machine_key`. |
| `env/simulated.py:_do_printer_push_driver` | plan silent; no server-side driver action existed | An estate-wide driver fault has no canonical repair otherwise: `canonical_resolutions()` receives only a `Placement` and cannot enumerate the machines that need fixing. A server-side publish is also what a shared printer on a print server actually offers, so this is the honest model rather than a convenience. |
| `env/simulated.py:_do_machine_clear_disk` | `float(a.args.get("gb", "0"))` | A missing `-gb` returned `ok=True` having freed nothing, logging a mutation against the technician for a no-op. Now a rejection, matching `mail.set_quota`, so `DispatchTool`'s "a rejected call never reached the environment" rule keeps the grade honest. (Carried from Phase 2a's open threads.) |
| `faults/catalog/mail.py:_mailbox` | raises when the mailbox is missing, because "the world was built wrong" | True until `mail.remove_mailbox` existed. A technician who deletes a mailbox then made `is_present()` raise, turning a bad grade into a 500. `_mailbox_is_gone()` now guards each mailbox-scoped `is_present()`, which reads **still present** — the person cannot send mail now either — while the deletion is reported separately as collateral damage. `apply()` keeps the raising version, where a missing mailbox really is a malformed world. |
| `session/queue.py:forgive` | rebuild a `Baseline` naming each field | Correct as written and a trap as a pattern: a field added to `Baseline` and forgotten here defaults to empty on every arrival, so its invariant never fires in a real session while its own unit tests keep passing. Both mail invariants shipped inert that way for one commit. Every field is named now, and `test_forgiving_nothing_leaves_every_baseline_field_intact` fails if the next one is not. |
| `session/store.py:Store` | one database, unscoped reads | `~/.vitsc/sessions.sqlite3` outlives the process, so `build_shift_report()` was summing previous shifts: four tickets closed reported seven. No timestamp could separate two runs — the simulated clock restarts at 09:00 every session — so rows carry a `session_id` and reads scope to it. `all_sessions=True` keeps the cross-run view available. |
| `web/routes/close.py:close_ticket` | `Disposition.ESCALATED` reachable from the close dropdown | Phase 2a left two paths to one disposition and they were not equivalent: this one skipped `review_escalation`, so it never bounced a fixable fault and produced a report with no `tier2_note` — the only place `escalation_reason` is spoken. Removed from the template *and* refused by the route, because a template-only fix leaves the unreviewed path open to anything posting the form. |
| `tests/test_end_to_end.py:HTTP_FIX` | one `(tool, command)` pair per fault | Two Phase 2b repairs genuinely need two world changes (enable *and* start a disabled service; re-enable DHCP *and* take a lease), and `resolve_via_http` posted only the first action — so the ticket closed with the fault still present, which reads as a grading bug rather than a stale table. Now an ordered list per fault, with a guard asserting the step count matches the canonical path's action count. |
| `tests/test_end_to_end.py`, `tests/test_web_close.py` | compare `canonical_title` against rendered HTML as a raw substring | `root_cause` is autoescaped, so a title containing an apostrophe ("the site's servers") failed the positive check — and made the *negative* leak check above it pass vacuously, for exactly the titles most likely to leak. Both compare the escaped form. The mail quota invariant's message also dropped its possessive so the same trap is not re-armed in `invariants.py`. |
| `tests/test_queue.py:test_easier_faults_are_dealt_more_often` | one test asserting share-of-draw ordering by difficulty level | Two claims in one. Share per *level* is `weight × how many faults sit at that level`, so it moves as the catalog grows and a fourth difficulty-3 fault failed a test about weighting. Split into a per-fault mechanism claim (true at any catalog size) and a catalog-composition claim, which is the one a badly-chosen difficulty should fail. |
| `tests/test_cascade.py`, `tests/test_queue.py` | a fixed seed's arrival is one ticket | Only ever true while cascades were nearly unreachable. With five of them, seed 2 deals one: a "single reporter" test was asserting something about the seed, and a no-re-deal test counted a cascade's own siblings as re-deals. Both now name their fault or compare against the whole arrival — convention 24, hit twice more. |
| `src/vitsc/data/company.yaml` | four printers | Every printer was installed on some workstation, so the `printer.offline_unused` distractor had **zero placements** and its conformance cases silently vanished rather than failing. PRT-OPS-02 is a spare nobody has installed, and `test_every_distractor_has_somewhere_to_land` now catches the class. |
