# Phase 2a: load-bearing facts per task

Moved out of the root `CLAUDE.md`, which points here. Per-task detail beyond this is in git history and the PRs.

- **Task 1**: leak terms bind per *ticket*, not at persona construction — `Persona.for_fault(leak_terms) -> Persona`, resolved via `SessionQueue.persona_for(ticket)`. Leak terms reach `scrub()` only, never a prompt.
- **Task 2**: `persona/config.py:PersonaSettings.from_env()`/`build_persona()` wire `VITSC_PERSONA`/`VITSC_BASE_URL`/`VITSC_MODEL` into `AppSession.build`; the default and any unrecognised backend fall back to `template` rather than raising. `AppSession.degraded` reads through to `queue.persona.degraded`, driven by the SSE payload rather than initial render.
- **Task 3**: the `Distractor` protocol (`distractors/base.py`) and its conformance harness (`tests/test_distractors.py`) — a distractor has no `is_present`/`symptoms`/`canonical_resolutions`, and `tests/test_architecture.py` forbids any `tools/` module importing `vitsc.distractors`, same as it forbids `vitsc.faults`.
- **Task 4**: `distractors/catalog.py` ships five distractors, applied by `session/queue.py:seed_distractors()` *before* `capture_baseline` (same capture-after-apply ordering as faults). `distractor_count` defaults to 0 (existing tests stay deterministic); `AppSession.build` passes 3.
- **Task 5**: cascades — one fault instance can produce several tickets. `FaultBase.reporters()` (default `None`) is resolved by `session/queue.py:resolved_reporters()`; `SessionQueue.open_ticket()` returns `list[Ticket]` capped by `CASCADE_MAX = 3`, sharing one `cascade_id`. `priority_for(fault, user, reporters=1)` escalates to P1 at 3+ reporters.
- **Task 6**: cascade-aware grading — `grading.py:duplicate_mutations(ticket, siblings=None)` counts a fix repeated once per sibling ticket instead of once for the shared cause, and never affects `correct`/`fault_cleared`. `afteraction.py:AfterAction.cascade_note` names the shared root cause; `store.py` persists `cascade_id`.
- **Task 7**: `print.server_spooler_stopped` (`faults/catalog/printing.py`) is the reference cascade fault — the first to override `reporters()` with an explicit list. `web/templates/_queue.html` tags sibling rows with `cascade_id` but leaves them unmerged, so the technician has to notice the pattern.
- **Task 8**: a deterministic simulated tier-2. `Ticket.escalate()`/`reopen()`/`accept_escalation()` and `TicketState.AWAITING_TIER2`; `session/tier2.py:review_escalation()` checks ownership (`escalation_is_correct`) *before* evidence — a fixable fault is bounced regardless of note quality. `Grade.escalation_quality` never affects `correct`.
- **Task 9**: the tier-2 flow reaches the app — `web/routes/escalate.py`'s `GET`/`POST /ticket/{id}/escalate`; `render_after_action()` was extracted out of `close_ticket()` so both routes share one after-action path. `AfterAction`'s verdict chain checks `escalation_quality == "bounced"` *before* `grade.correct`, since a bounced-then-fixed ticket is `correct=True` by design.
- **Task 10**: the original-content knowledge base (`kb/models.py:Article`, `kb/loader.py:load_articles()`, 8 hand-authored articles under `src/vitsc/data/kb/`). `tests/test_kb.py:test_no_article_is_an_answer_key` proves no article names a fault's id or title. `Fault.kb_articles` links 8 faults to articles today.
- **Task 11**: the `kb` tool (`tools/kb.py:KnowledgeBase`, a plain `Tool` not `DispatchTool`) and `AfterAction.kb_suggestions` — links each `fault.kb_articles` entry, marked read/unread, plus a line per seeded distractor's `note`. `Grade.kb_consulted` is diligence-only, feeds no correctness field.
- **Task 12**: the mail world model — `MailRule`/`Mailbox`/`MailSystem` in `world/models.py`; `World.mail` is a required field, one `Mailbox` derived per user's `upn` in `seed.py:load_world()`. No mail fault exists yet to consume it.
- **Task 13**: mail query/action kinds in `env/simulated.py` (`mail.mailbox`/`mail.rules`/`mail.queue`, `mail.set_quota`/`mail.archive`/`mail.remove_rule`/`mail.restart_transport`). `mail.archive` reduces `used_mb` to 10% of *current* quota, per the `__init__`-after-`apply()` gotcha below.
- **Task 14**: the mail console tool — `tools/mail.py:MailConsole`, a `DispatchTool` overriding `target_key()` so `get-queue`/`restart-transport` target `args["host"]` instead of `args["sam"]`. Tool roster is now eight (`tools/registry.py`).
- **Task 15**: the two reference mail faults (`faults/catalog/mail.py`), bringing the catalog to thirteen. `mail.mailbox_full` is the clearest demonstration that the gate is world state — `mail.set_quota` and `mail.archive` both clear it and neither is "the" answer — and is in `session/ticket.py:WORK_STOPPING`. `mail.external_forwarding_rule` is the third escalate-correct fault, and the three are escalate-correct for three *different* reasons: authorisation (`ad.offboarded_reactivation`), hardware (`endpoint.failing_disk`), and acting-being-itself-the-mistake (this one). Both link the previously orphaned `mail-cannot-send-or-receive` KB article. `escalation_evidence` names `mail.rules` explicitly even though `tier2.py` would fall back to `diagnostic_path()` anyway — the fault is stating what tier-2 wants quoted, not relying on a default. The module itself came from PR #9, which implemented this task in parallel; this branch kept it and fixed the `is_present()` gate (see the table below).
- **Task 16**: end-to-end coverage for every Phase 2a surface (`tests/test_end_to_end.py`) — a cascade worked through HTTP (three tickets, one `restart-spooler`, three clean closes), a bounced escalation recovered, both mail faults (the resolvable one and the escalate-correct one), and a full pass with distractors seeded proving they are never blamed on the technician. `HTTP_FIX` is now guarded by set *equality* against the non-escalate-correct roster in both directions, plus a check that every entry names a command the tool actually registers.
