# vitsc package notes

Per-package detail, moved out of the root `CLAUDE.md` (which keeps the core design principle, the layer
diagram and the guarantees table). Paths below are relative to `src/vitsc/` unless they start with `tests/`.

- **`vitsc.world`** — pydantic entities (`World`, `ADUser`, `ADGroup`, `Machine`, `Printer`, `PrintJob`, `Process`, `Share`, `Network`, `MailSystem`, `Mailbox`, `DistributionList`), the `company.yaml` seed loader (`world/seed.py`, always returns a healthy world — faults are what break it; the estate is 20 users and 10 workstations, so half the org shares a terminal and a machine-placed fault is not a user-placed fault under another name), and invariant checking (`world/invariants.py`: a `Baseline` captured *after* faults are applied, so only *collateral* damage from a bad fix trips it, never the fault itself being present; the mail pair — a deleted mailbox, a quota set below usage — landed in 2b once there were mail faults to test it against). Two Phase 2b subtleties: **group membership is asked two ways on purpose** — `groups_of()` is direct membership, which is what `MemberOf` shows on the account, while `is_member()`/`effective_members()` follow nesting, which is what a file server asks; noticing the difference is `ad.nested_group_membership`'s whole diagnosis. And **`Network.netmask` is derived from `subnet` rather than stored**, for the same reason `Machine.dhcp_reserved_ip` exists beside `ip`: a fault that rewrites a machine's mask must not be able to rewrite the value a repair restores it to.
- **`vitsc.env`** — the `Environment` protocol (`read`/`execute`/`snapshot`/`restore`) and `SimulatedEnvironment`, which dispatches `Query.kind`/`Action.kind` strings (e.g. `"ad.user"`, `"machine.renew_dhcp"`) to `_read_*`/`_do_*` methods by name via `getattr`. Adding a new query/action kind means adding a matching `_read_<kind>`/`_do_<kind>` method (dots become underscores). Phase 2b gave it a **routing model**: `_reachable()` decides whether a packet gets anywhere (on-subnet needs no router; otherwise the gateway must be inside the machine's own subnet as the machine computes it — wrong mask included — *and* be the address the site's router answers on), and `_resolve()` additionally requires a running `Dnscache` and a reachable resolver. That is what makes a wrong mask, a wrong gateway, a dead resolver, a disabled DNS client and a stale proxy five distinguishable tickets instead of five spellings of one. A machine on an APIPA address consequently has no route at all, which is what `ipconfig` already rendered as a blank gateway.
- **`vitsc.faults`** — the `Fault` protocol (`vitsc/faults/base.py`): `placements()` finds valid targets in a `World`, `apply()` mutates it, `is_present()` is the single source of truth for both "is it broken" and "was it fixed", `symptoms()` returns only what a non-technical user could perceive (must contain no leaked jargon — see below), `diagnostic_path()` declares which queries should reveal it, `canonical_resolutions()` is documentation/test fixture only, never the pass/fail gate. The protocol grew in Phase 2a (`kb_articles`, `escalation_is_correct`/`escalation_reason`/`escalation_evidence`, `reporters()`); `FaultBase` carries the defaults for every optional member so the ten pre-2a faults conform without ten copy-pasted stubs, and a new fault that overrides nothing still satisfies the protocol. `reporters()` returning a list is what makes a fault a *cascade* — one placement, several tickets. New faults self-register via `register()` in `vitsc/faults/registry.py` at import time; `catalog/__init__.py` is what triggers that registration. The catalog is thirty-two faults across five domains: identity (8), network (6), printing (6), endpoint (6), mail (6). A fault's `leak_terms` are matched by `persona.client.scrub()` anchored at a word *start*, so a term catches its own inflections (`"lock"` → "locking") without firing on words that merely contain it (`"lease"` does not match "please"); write a term with a trailing space (`"ad "`) to mean the whole word only.
- **`vitsc.distractors`** — the `Distractor` protocol (`distractors/base.py`) and an eleven-entry catalog, sized by a *ratio* to the fault count rather than a fixed number: the same handful of anomalies against thirty-two faults stops being noise and becomes a tell a technician learns to skip. Deliberately a *narrower* contract than `Fault`: no `is_present()`, no `symptoms()`, no `canonical_resolutions()`, no `escalation_is_correct`. A distractor is world noise that is never anybody's ticket, applied by `session/queue.py:seed_distractors()` *before* `capture_baseline`, so it can never be mistaken for the technician's collateral damage. Its `note` is what the after-action quotes to name it as pre-existing.
- **`vitsc.kb`** — the original-content knowledge base: `kb/models.py:Article`, `kb/loader.py:load_articles()`, and fifteen hand-authored Markdown articles under `src/vitsc/data/kb/`, with no orphans in either direction (see the guarantees table). Articles are procedural ("check the mailbox against its quota"), never answer keys — a test proves no article names a fault's id or title. `Fault.kb_articles` links a fault to the articles that would have helped, which the after-action renders as read/unread.
- **`vitsc.tools`** — seven thin `DispatchTool` subclasses (`vitsc/tools/base.py`), plus the plain-`Tool` `kb` described above, that map command names to read/write `Query`/`Action` kinds and render output in the shape of the real utility (e.g. `Get-ADUser`-style field dumps, `ipconfig`-style block). Every call is logged to a `ToolLog`, which is what `session/grading.py` reads for tool efficiency and whether the technician looked before touching — so `mutating` on a `ToolCall` must stay honest (a rejected call that never reached the environment is not a mutation). `PowerShellConsole` is a *defined* command set, not a parser — anything outside it returns the same `CommandNotFoundException` text the real shell would, deliberately, rather than faking a general shell.
- **`vitsc.persona`** — the `Persona` protocol (`persona/models.py`) plus `PersonaCard` (built from an `ADUser` by `persona/personas.py:card_for`, seeded off `sam` so a person's mood/literacy is stable across sessions) and `TemplatePersona` (`persona/templates.py`), the model-free fallback. A persona's signatures take only a card and a `UserSymptoms` — never a `World` or a `Fault` — which is leak-prevention layer 1, enforced structurally. `TemplatePersona` keyword-matches the technician's question onto a symptom field and deflects everything else; it is what the whole test suite uses, so nothing downstream can depend on a model being loaded. `LMStudioPersona` (`persona/client.py`, constructed from `persona/config.py` when `VITSC_PERSONA=lmstudio`) talks to an OpenAI-compatible endpoint on `localhost:1234` and adds leak-prevention layers 2 (`persona/prompts.py` forbids guessing a cause) and 3 (`scrub()` against the fault's `leak_terms`, one retry with a nudge, then deflect). Every failure path — model down, slow, absent, or leaking twice — returns `TemplatePersona` output and sets `degraded`; the drill stays fully playable with nothing running locally, and `openai` is imported lazily inside `make_client()` so the suite never touches it.
- **`vitsc.session`** — `session/shift.py` is the fixed eight-hour shift: `Shift` (simulated 09:00–17:00, eight real minutes at one sim-minute per second) and `build_shift_report()`, which sums the day from the *store's* rows so the summary cannot disagree with the history page — `unresolved` is the one exception and comes from the live queue, because a ticket nobody closed was never written to the store. The shift gates `SessionQueue.tick()` only: arrivals stop, tickets already open stay workable, and `open_for()`/`open_cascade()` are unaffected. `session/ticket.py` holds `Ticket` (the whole record of one job: persona, symptoms, chat, tool calls, actions, disposition), `Priority`/`SLA_MINUTES`, and `priority_for(fault, user)`, the system's triage call that the player's `user_priority` is graded against. This is the first layer that knows a fault *id*, but only as an opaque string — grading still asks `is_present()` against the world rather than trusting the ticket. `Ticket.close()` takes an explicit `at`, because SLA timing runs on the simulated `world.clock`, never wall time. `session/queue.py`'s `SessionQueue` is the scheduler: it picks an unheld, not-already-present fault+placement, applies it, and opens a ticket whose text came from the persona. **It picks the fault first, weighted by `DIFFICULTY_WEIGHTS` (5/4/3/2/1), then a placement uniformly** — `choose_fault_and_placement()`. Drawing uniformly from `(fault, placement)` pairs, as it did before Phase 2b, weighted every fault by how many targets it happened to have: the catalog's only cascade has one placement and a mailbox fault has twenty, so the cascade was dealt twenty times less often for no reason anyone chose. A fault's `difficulty` is therefore load-bearing — it is a frequency decision as much as a hardness one — and `placements()` no longer controls how often a fault comes up. Its `baseline` **accumulates** rather than re-snapshotting — `forgive()` excuses only the delta the newly applied fault made, so a technician's collateral damage from an earlier ticket stays visible for the rest of the session instead of being laundered by the next arrival. `session/tier2.py:review_escalation()` is the deterministic simulated tier-2 — template-driven and model-free for the same reason `TemplatePersona` is — judging *ownership* before evidence, so a fixable fault is bounced back however well the note is written. `session/grading.py` and `session/afteraction.py` close the loop: `grade_ticket()` asks `is_present()` and `check_invariants()` (never "did they use the canonical fix"), and `build_after_action()` names the root cause the player was never told, binds the fault's `diagnostic_path` into a shortest path, and picks a verdict from what the technician *did* — `Disposition` and `fault_cleared` separately, not from `disposition_correct`, which folds both together.
